# 화면 구조 & 사용자 흐름

모바일 세로 기준. 하단 탭 네비게이션 + 엄지 도달 영역 조작.

## 1. 화면 목록

```
┌─────────────────────────────────────────────┐
│ 하단 탭: [홈] [학습] [오답] [통계] [설정]      │
└─────────────────────────────────────────────┘

홈 (/)             대시보드: D-day, 오늘의 진행률, 예상점수,
                   영역별 정답률 요약, "오늘의 학습 시작" 버튼
학습 (/study)       오늘의 문제 세션 (풀이 → 확신도 → 채점 → 해설/SQL단계)
오답 (/review)      오답노트 + 복습 대기 목록 (틀린 문제 다시 풀기)
통계 (/stats)       영역별·유형별 정답률, 예상점수 상세
설정 (/settings)    시험일, 하루 목표 문제 수, 데이터 초기화
```

## 2. 핵심 흐름 — 오늘의 학습 세션

```
[홈] "오늘의 학습 시작"
   │
   ▼
[학습] 문제 카드 (1/20)
   │  ├─ 보기 4~5개 (탭하여 선택, 하단 큰 버튼)
   │  ├─ 확신도 선택: 확실함 / 애매함 / 찍음
   │  └─ [정답 확인] (하단 고정 CTA)
   ▼
채점 결과
   │  ├─ 정답/오답 표시 + 선택보기 하이라이트
   │  ├─ 해설
   │  ├─ (SQL문제) 단계별 실행 결과 아코디언
   │  │     FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
   │  ├─ 오답이면 → attempt 저장 + 복습 스케줄(1일) 자동 등록
   │  └─ [다음 문제] (하단 고정 CTA)
   ▼
... 반복 ...
   ▼
세션 완료 요약
   ├─ 오늘 정답률, 확신도 대비 정답 (찍었는데 맞음 등)
   ├─ 갱신된 예상점수
   └─ [홈으로] / [오답 복습하기]
```

## 3. 오늘의 문제 구성 로직 (repository.getTodaySet)

```
목표 = daily_goal (기본 20)

1) 복습 대기 문제 (due_at <= now) 를 우선 채움  ← 최우선
2) 남는 자리를 신규(아직 안 푼) 문제로 채움
     - subject 가중: SQL 70% / 데이터모델링 30%
     - 오답 이력 유형 우선
3) 그래도 부족하면 과거 문제 재출제(정답률 낮은 유형 우선)

세션 내 순서: 복습 → 신규 섞기(집중 저하 방지),
동일 유형 연속 최대 3개 제한.
```

## 4. 상호작용 원칙 (한 손 UI)

- 주요 CTA(정답확인/다음)는 **화면 하단 고정**, 최소 높이 56px.
- 보기 버튼은 세로 스택, 각 항목 큰 터치 영역(48px+).
- 상단은 정보(진행률, D-day)만. 조작은 하단.
- 스와이프 없이 탭만으로 완주 가능(오조작 방지).
- 색: 정답 초록, 오답 빨강, 확신도 3색 칩.

## 5. 상태 (진행 중 세션)

- 세션은 `sessionStorage`에 진행상황 보관 → 앱 전환/새로고침에도 이어풀기.
- 각 문제 채점 즉시 `attempt` 저장(중간 이탈해도 기록 남음).
