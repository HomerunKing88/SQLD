# SQLD 30일 코치 설계

## 요구사항 → MVP 결정
| 요구 | MVP 구현 |
|---|---|
| 52점에서 60점 | 첫 화면에 `D-30`, SQL 중심 루틴, 예상 점수와 남은 점수 노출 |
| 하루 20~30분 | 20문제 세트, 한 화면 한 문제, 하단 고정 탭 |
| 객관식·확신도·해설 | 4지선다, 확실함/애매함/찍음, 채점 뒤 해설 |
| SQL 실행 흐름 | JOIN 문제에서 6단계 결과 패널 |
| 오답·간격 반복 | 로컬 MVP 진행값 + Supabase `review_queue` 1/3/7일 데이터 모델 |
| 분석 | 영역 정답률 및 최근 결과 기반 예상점수 카드 |

## 화면과 사용자 흐름
1. **오늘:** D-day와 진행률을 확인하고 문제를 하나씩 푼다.
2. **응답:** 보기 선택 → 확신도 탭 → 정답 확인.
3. **피드백:** 정답/해설 확인. SQL 문제는 실행 순서를 펼친다.
4. **다음:** 다음 문제로 이동하며 결과를 기록한다.
5. **복습:** 틀린 문제 수와 1·3·7일 재출제 방식을 확인한다.
6. **분석:** 영역별 취약도와 예상점수로 다음 행동을 정한다.

## 영속화 설계
- `attempts`에는 선택지, 확신도, 정오답, 시각을 남긴다.
- 오답이면 `review_queue`에 오늘+1/+3/+7일의 세 건을 upsert한다.
- 오늘의 큐는 기한이 지난 `review_queue`를 먼저, 이후 미완료 활성 문제를 채운다.
- 예상점수는 최근 모의고사/최근 영역별 정답률을 가중해 계산한다. MVP는 풀어본 문제 수로 간단히 시연한다.
